Introduction

As the project of the end of the year in my university, I decided to use AI in order to make classifying End of Studies Project (PFE in French) reports easier, more efficient and faster. Our university handles more than 3000 reports each year which can make manually classifying them labor-intensive and prone to human error, therefore I opted to use and finetune a Named Entity Recognition model (GLiNER) to extract metadata from the cover page then classifying the reports based on the results. [GLiNER Github repo].aside

Preparing the Dataset

Due to the unavailability of a large, pre-annotated dataset of actual PFE reports (partly due to privacy considerations and the effort required for manual annotation), a synthetic dataset was generated specifically for fine-tuning the GLiNER model.

The generation process involved:

  • Templates: Using various sentence structures that create an easy-to-understand phrasing using the variables usually found on the cover pages of academic reports (e.g., Pour l’année académique 2024/2025, l’étudiant Aymen Nasri de la spécialité ai travaille sur un projet intitulé PFE Reports Assistant en collaboration avec Terraform Group sous la supervision du professeur Yassine Miled).
  • Entity Generation: Populating these templates with realistic examples of the target entities:
    • Academic Years: Recent years in YYYY/YYYY+1 format.
    • Specialties: Common computer science specialties found at the institution (e.g., “AI”, “GL”, “Cybersecurity”, “Cloud”, “IoT”, “Gaming”), including common variations and acronyms (e.g., “Intelligence Artificielle”, “Génie Logiciel”, “IA”).
    • Project Titles: Realistic-sounding titles in French, relevant to each specialty.
    • Organizations: Real names of current Tunisian companies, universities, and public bodies that might collaborate on or host projects.
    • Student Names: Common Tunisian first and last names, generated randomly. Care was taken to avoid generating student last names identical to existing professor last names. Name casing (e.g., uppercase last names) was varied randomly.
    • Professor Names: Names drawn from a provided list professors_specialties.csv from the administration, with random variation in the casing of last names.
    • Volume: Generating a specified number of samples (800 examples without duplicates) to provide sufficient data for fine-tuning.
    • Format: Outputting the data in JSON format, where each entry contains the tokenized text and a list of ner annotations (start token index, end token index, entity label), compatible with the training requirements of the gliner library.

The primary goal of this synthetic dataset was to teach the pre-trained GLiNER model to accurately recognize the specific types of entities relevant to PFE reports within the expected linguistic context (primarily French, with some technical English terms).

Training and Evaluation Phase
